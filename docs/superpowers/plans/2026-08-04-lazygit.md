# lazygit Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Install lazygit from the dotfiles and manage its config, so the herdr auto-layout's `lazygit` tab has a working binary behind it on a fresh machine.

**Architecture:** One new Stow package (`lazygit/`, tracking only `config.yml`) plus an install block in `install.sh` that tries the system package manager and falls back to the upstream GitHub release tarball. Wiring follows the existing `herdr` package exactly: stow loop, `doctor.sh` `PACKAGES`, scoped `.gitignore` for tool-written state, one POSIX-sh test file.

**Tech Stack:** bash (`install.sh`, `doctor.sh`), GNU Stow, POSIX sh + `tests/lib.sh` for tests, YAML config.

**Spec:** `docs/superpowers/specs/2026-08-04-lazygit-design.md`

## Global Constraints

- **Conventional Commits**, imperative lower-case subject, scope preferred: `feat(install):`, `feat(lazygit):`, `test(lazygit):`, `docs(lazygit):`. Why goes in the body.
- **Every tool install is best-effort.** A failure prints `!! <tool> install failed — …` and continues. Never `exit`, never let `set -e` abort the run.
- **Cross-platform:** macOS (brew), WSL, Debian/Ubuntu (apt), Arch (pacman). No GNU-only flags in the install path.
- **Tests are POSIX `sh`**, sourced from `tests/lib.sh`, use `pass`/`fail`/`assert_eq`/`assert_contains`/`assert_not_contains`, end with `finish`. Optional dependencies print `  skip: …` rather than failing. `tests/run.sh` globs `test-*.sh` — no registration needed.
- **Stow uses `--no-folding`**, so `~/.config/lazygit` becomes a real directory holding per-file symlinks. Anything a tool writes there is a real file outside the repo, which `doctor.sh` reports as drift unless git-ignored.
- **The delta divergence is intentional:** lazygit's pager runs delta with `--no-gitconfig`, dropping the repo's `delta.side-by-side = true`. Never "align" it with the git config.
- Verify lazygit config keys against `lazygit --config` (prints the installed version's defaults) — not from memory.

**Interfaces:**
- Consumes: `pkg_install` (defined `install.sh:15`), which tries `brew install` / `sudo apt install -y` / `sudo pacman -S --noconfirm` and returns 1 if no manager is found.
- Produces: shell function `install_lazygit_release` (no args, returns 0 on success, 1 on any failure), and `lazygit` on `PATH` — depended on by the herdr auto-layout daemon enabled at `install.sh:260`.

**Why the ordering matters:** the auto-layout block near the end of `install.sh` enables a systemd user unit that opens a `lazygit` tab for every new worktree. The install must come before it.

- [ ] **Step 1: Write the failing test**

Create `tests/test-lazygit.sh`:

```sh
#!/bin/sh
# lazygit package: the binary is installed by install.sh (package manager first,
# upstream release tarball as fallback), the config pins the intended settings,
# lazygit's own state stays out of the repo, and the package is wired into
# install.sh / doctor.sh.
HERE="$(dirname "$0")"
. "$HERE/lib.sh"
REPO="$(cd "$HERE/.." && pwd)"

# ── install.sh: the install block ────────────────────────────
INST="$REPO/install.sh"

grep -q 'command -v lazygit' "$INST" \
  && pass "install.sh guards on lazygit already being present" \
  || fail "install.sh guards on lazygit already being present"

grep -q 'pkg_install lazygit' "$INST" \
  && pass "install.sh tries the system package" \
  || fail "install.sh tries the system package"

grep -q 'install_lazygit_release' "$INST" \
  && pass "install.sh has a release fallback" \
  || fail "install.sh has a release fallback"

# Upstream publishes lazygit_<version>_<Os>_<Arch>.tar.gz; the asset carries the
# version WITHOUT the tag's leading v. Getting this string wrong makes the
# fallback dead weight on the one platform that needs it (Ubuntu LTS, where
# lazygit is absent from the archive entirely).
grep -q 'jesseduffield/lazygit/releases/download' "$INST" \
  && pass "release fallback points at the upstream download URL" \
  || fail "release fallback points at the upstream download URL"

grep -q 'lazygit_${ver}_${os}_${arch}.tar.gz' "$INST" \
  && pass "release asset name matches upstream's naming" \
  || fail "release asset name matches upstream's naming"

# Best-effort: a failed install must warn, not abort the run.
grep -q '!! lazygit install failed' "$INST" \
  && pass "lazygit install failure warns instead of aborting" \
  || fail "lazygit install failure warns instead of aborting"

# ── Ordering: lazygit before the auto-layout daemon ──────────
# The daemon enabled at the end of install.sh runs lazygit in every new
# worktree's second tab; installing it afterwards leaves a fresh machine with a
# tab that dies on launch.
lg_line="$(grep -n 'command -v lazygit' "$INST" | head -1 | cut -d: -f1)"
al_line="$(grep -n 'herdr-autolayout.service' "$INST" | head -1 | cut -d: -f1)"
if [ -n "$lg_line" ] && [ -n "$al_line" ] && [ "$lg_line" -lt "$al_line" ]; then
  pass "lazygit is installed before the auto-layout daemon is enabled"
else
  fail "lazygit is installed before the auto-layout daemon is enabled (lazygit@${lg_line:-?} autolayout@${al_line:-?})"
fi

bash -n "$INST" && pass "install.sh parses" || fail "install.sh parses"

finish
```

- [ ] **Step 3: Add the install block to `install.sh`**

Insert after the herdr block (after line 210, the closing `fi` of the herdr install) and before the `# ── Nerd Font` comment:

```bash
# ── lazygit (git TUI) ────────────────────────────────────────
# Must come before the auto-layout section at the end of this script: that
# daemon opens a `lazygit` tab in every new worktree, so without the binary a
# fresh machine gets a tab that dies on launch.
#
# Package managers first — brew and pacman track current, Debian trixie has
# 0.50 — but lazygit is missing from older Ubuntu's archive entirely, so fall
# back to the upstream release tarball into ~/.local/bin (same shape as the
# win32yank block above).
install_lazygit_release() {
  local ver os arch url tmp
  ver="$(curl -fsSL https://api.github.com/repos/jesseduffield/lazygit/releases/latest \
         | sed -n 's/.*"tag_name": *"v\{0,1\}\([^"]*\)".*/\1/p' | head -1)" || return 1
  [ -n "$ver" ] || return 1
  case "$(uname -s)" in
    Linux)  os=Linux  ;;
    Darwin) os=Darwin ;;
    *) return 1 ;;
  esac
  case "$(uname -m)" in
    x86_64|amd64)  arch=x86_64 ;;
    arm64|aarch64) arch=arm64  ;;
    *) return 1 ;;
  esac
  # Asset name repeats the version WITHOUT the tag's leading v.
  url="https://github.com/jesseduffield/lazygit/releases/download/v${ver}/lazygit_${ver}_${os}_${arch}.tar.gz"
  tmp="$(mktemp -d)" || return 1
  if curl -fsSL "$url" -o "$tmp/lazygit.tar.gz" \
     && tar -xzf "$tmp/lazygit.tar.gz" -C "$tmp" lazygit; then
    mkdir -p "$HOME/.local/bin"
    install -m 755 "$tmp/lazygit" "$HOME/.local/bin/lazygit"
    rm -rf "$tmp"
    return 0
  fi
  rm -rf "$tmp"
  return 1
}

if ! command -v lazygit &>/dev/null; then
  echo "Installing lazygit..."
  pkg_install lazygit || install_lazygit_release \
    || echo "!! lazygit install failed — install manually: https://github.com/jesseduffield/lazygit/releases"
fi
```

**Background you need:**
- `git/.config/git/config` sets `core.pager` as a *guarded* expression (`command -v delta >/dev/null 2>&1 && delta || less`) because a missing pager is fatal to git. `tests/test-git-delta.sh` proves that guard behaviourally with stubbed binaries on a narrowed `PATH`. Do the same here.
- delta is installed best-effort (`ensure_tool git-delta delta`, `install.sh:110`), so a machine can genuinely lack it.
- delta's `-s/--side-by-side` is a plain flag — it cannot be switched off with `=false`. `--no-gitconfig` (verified present in delta 0.18.2) is how the repo's `delta.side-by-side = true` gets overridden for lazygit's half-width panel.
- lazygit runs the pager string through a shell — upstream's own docs use a pipeline (`diff-so-fancy | less …`) as an example value — which is what makes the `||` fallback viable.

- [ ] **Step 1: Write the failing tests**

Insert into `tests/test-lazygit.sh`, after the `bash -n "$INST"` assertion and **before** `finish`:

```sh
# ── The lazygit Stow package ─────────────────────────────────
CONF="$REPO/lazygit/.config/lazygit/config.yml"

[ -f "$CONF" ] && pass "config.yml exists" || fail "config.yml exists"

# Valid YAML (skip where PyYAML isn't available)
if command -v python3 >/dev/null 2>&1 && python3 -c 'import yaml' 2>/dev/null; then
  if python3 -c 'import yaml,sys; yaml.safe_load(open(sys.argv[1]))' "$CONF" 2>/dev/null; then
    pass "config.yml is valid YAML"
  else
    fail "config.yml is valid YAML"
  fi
else
  echo "  skip: python3 PyYAML unavailable (YAML validation)"
fi

# Pinned settings
grep -q 'colorArg: always'      "$CONF" && pass "colorArg always"       || fail "colorArg always"
grep -q 'editPreset: nvim'      "$CONF" && pass "editPreset nvim"       || fail "editPreset nvim"
grep -q 'nerdFontsVersion: "3"' "$CONF" && pass "nerdFontsVersion 3"    || fail "nerdFontsVersion 3"

# ── The pager expression ─────────────────────────────────────
# Single-quoted YAML scalar, so plain sed extraction works and the behavioural
# check below needs no YAML parser.
PAGER_EXPR="$(sed -n "s/^[[:space:]]*pager:[[:space:]]*'\(.*\)'[[:space:]]*\$/\1/p" "$CONF" | head -1)"
[ -n "$PAGER_EXPR" ] && pass "pager expression extracted" || fail "pager expression extracted"

# delta's side-by-side layout is right for a full-width terminal and wrong for
# lazygit's half-width diff panel, which is why the repo's delta.side-by-side
# is dropped with --no-gitconfig. Lock the divergence in so a future
# copy-paste from git/config can't quietly undo it.
assert_contains "$PAGER_EXPR" "--no-gitconfig" "pager ignores the repo's delta gitconfig"
assert_not_contains "$PAGER_EXPR" "side-by-side" "pager doesn't force side-by-side"

# Behavioural: run the real expression with stubbed binaries, exactly as
# tests/test-git-delta.sh does for core.pager.
BIN="$(mktemp -d)"
trap 'rm -rf "$BIN"' EXIT INT TERM
printf '#!/bin/sh\necho USED_DELTA\n' >"$BIN/delta"
printf '#!/bin/sh\necho USED_LESS\n'  >"$BIN/less"
chmod +x "$BIN/delta" "$BIN/less"

# PATH is narrowed inside the child, not as an assignment prefix — the latter
# would hide the `sh` binary we're trying to launch.
run_expr() { echo x | sh -c "PATH='$BIN'; $1" 2>/dev/null; }

assert_eq "$(run_expr "$PAGER_EXPR")" "USED_DELTA" "pager uses delta when installed"
rm -f "$BIN/delta"
assert_eq "$(run_expr "$PAGER_EXPR")" "USED_LESS"  "pager falls back to less without delta"

# ── Tool-written state stays out of the repo ─────────────────
# --no-folding makes ~/.config/lazygit a real dir, so lazygit's state.yml is a
# real file outside the repo; doctor.sh skips anything git check-ignore matches.
git -C "$REPO" check-ignore -q "lazygit/.config/lazygit/state.yml" \
  && pass "git-ignored: state.yml" || fail "git-ignored: state.yml"

# ── Package machinery ────────────────────────────────────────
grep -Eq 'for pkg in .*\blazygit\b' "$INST" \
  && pass "install.sh stows lazygit" || fail "install.sh stows lazygit"
grep -Eq 'PACKAGES=.*\blazygit\b' "$REPO/doctor.sh" \
  && pass "doctor.sh scans lazygit" || fail "doctor.sh scans lazygit"
bash -n "$REPO/doctor.sh" && pass "doctor.sh parses" || fail "doctor.sh parses"
```

- [ ] **Step 4: Create the config**

Create `lazygit/.config/lazygit/config.yml`:

```yaml
# lazygit — https://github.com/jesseduffield/lazygit/blob/master/docs/Config.md
# Managed by dotfiles. Only this file is tracked; lazygit's own state.yml in the
# same directory is git-ignored. Verify key names with `lazygit --config`, which
# prints the installed version's defaults — unknown keys are ignored silently.

git:
  paging:
    # lazygit passes --color=always to git diff so delta gets colour down the pipe.
    colorArg: always
    # Guarded like git's core.pager: delta is installed best-effort, and lazygit
    # runs this string through a shell (upstream's docs use a pipeline as the
    # example value), so the || fallback works and a delta-less machine still
    # gets readable diffs.
    #
    # --no-gitconfig deliberately drops ~/.config/git/config's delta block.
    # That sets side-by-side = true, which is right for a diff filling the
    # terminal and wrong for lazygit's half-width panel — two unreadable
    # columns. delta's -s/--side-by-side is a plain flag and can't be switched
    # off with =false, so dropping gitconfig is the way to override it. This
    # inconsistency with the git config is intentional; don't "fix" it.
    pager: 'command -v delta >/dev/null 2>&1 && delta --no-gitconfig --paging=never || less'

os:
  # Match EDITOR/VISUAL from ~/.config/shell/env.sh rather than letting lazygit guess.
  editPreset: nvim

gui:
  # install.sh places the Monaspace Nerd Font, so the glyph set is available.
  nerdFontsVersion: "3"
```
